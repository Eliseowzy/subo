# 界面多语言规范

本文是**写界面代码时的规矩**。新增页面、组件、提示语，都按这里来；不按这里来的代码过不了
`npm run build`。

## 1. 一句话

> 界面代码里不出现任何给人看的自然语言。所有文案都放在 `app/src/i18n/locales/` 的语言文件里，
> 代码里只写键：`t("home.recent")`。

## 2. 目录

```
app/src/i18n/
├── index.tsx        # t() / tx() / useLocale() / setLocale() / LOCALES，一般不用改
├── types.ts         # 由基准语言推出的类型：Key、Messages、Locale、defineLocale
├── locales/
│   ├── zh-CN.ts     # 基准语言：所有键先在这里定义，结构以它为准
│   ├── en.ts        # English
│   ├── zh-TW.ts     # 繁體中文
│   ├── ja.ts        # 日本語
│   └── ko.ts        # 한국어；其他语言均用 defineLocale，缺键、多键 tsc 报错
└── packages/        # 宏包说明的译文（可选），见第 7 节
```

`locales/` 下的文件由 `import.meta.glob` 自动收录：**放进去就生效，不用登记**。
语言菜单（首页左栏「语言」、工作区顶栏地球图标）从收录结果生成，也不用改。

## 3. 写界面时怎么用

```tsx
import { t, tx, useLocale } from "./i18n";

export default function Foo() {
  useLocale();                                   // 订阅语言：切换时本组件重渲染
  return (
    <button title={t("foo.saveTitle")}>          // 属性
      {t("foo.save")}                            // 文本
      {t("foo.count", { count: n })}             // 插值、复数
      {tx("foo.press", { kbd: <Kbd>⌘↵</Kbd> })}  // 文案里嵌组件
    </button>
  );
}
```

规则：

1. **组件里用了 `t()`，就在组件开头调一次 `useLocale()`**，否则切换语言时它不会刷新。
   需要语言代码时用返回值：`const locale = useLocale(); x.toLocaleString(locale.code)`。
2. **非组件代码**（toast、工具函数、CodeMirror 扩展）直接 `t()`，取的是调用那一刻的语言。
   有缓存的（如补全列表）按 `getLocale()` 做缓存键，参见 `latex.ts`。
3. **不要拼句子**。`"共 " + n + " 个"`、`` `${a}（${b}）` `` 这类拼法换到别的语言语序就错了；
   整句写进语言文件，用 `{name}` 占位。
4. **数量相关的写复数**：英文 `{ one: "{count} error", other: "{count} errors" }`，
   中文写一个字符串即可；调用时传 `count`。规则由 `Intl.PluralRules` 按语言决定。
5. **日期、相对时间、数字交给 `Intl`**，传 `locale.code`：
   `Intl.RelativeTimeFormat`、`toLocaleDateString`、`toLocaleString`。不要在语言文件里写「分钟前」。
6. **要嵌组件就用 `tx()`**，不要把一句话拆成「前半句 + `<Kbd>` + 后半句」三个键。
7. 快捷键写 `⌘`，`<Kbd>` 会按平台换成 `Ctrl+`；写在纯文本（如 `title`）里的 `⌘` 目前不换。

## 4. 键怎么起

- 第一层按**界面区域**分组：一个页面或独立组件一组（`home`、`workspace`、`preview`、`attach`……），
  跨页面复用的放 `common`，品牌放 `brand`，时间格式放 `time`。
- 新页面就新开一组，组名与组件名对应（`Settings.tsx` → `settings`）。
- 组内用小驼峰，描述**用途**而不是内容：`saveFailed`，不是 `baoCunShiBai` 也不是 `saveFailedPleaseRetry`。
- 同一控件的标签和提示配对：`openFolder` / `openFolderTitle`；无障碍名用 `…Label`。
- 子状态较多时再嵌一层：`workspace.status.running`、`workspace.save.dirty`。
- 键一旦发布不要改名，改文案只改值；确实要改名时全仓替换，`tsc` 会指出漏网的。

## 5. 新增一条文案

1. 在 `locales/zh-CN.ts` 对应分组里加键和中文。
2. 在**每一个**其他语言文件里加同名键和译文。漏了 `npx tsc --noEmit` 会报
   `Property 'xxx' is missing`，这是故意的：不允许出现「只有中文有」的文案。
3. 代码里 `t("分组.键")`，键写错同样 tsc 报错（`Key` 是全部合法键的联合类型）。

## 6. 新增一种语言

线性扩展，只动一个新文件：

1. 复制 `locales/en.ts` 为 `locales/<代码>.ts`，代码用 BCP 47（`ja`、`zh-TW`、`fr`）。
2. 改 `code`（与文件名一致）、`name`（用该语言自己写：`日本語`，不是「日语」）、译文。
3. `npx tsc --noEmit` 通过即完整；启动后语言菜单里自动出现。
4. 浏览器语言会自动匹配：先精确匹配，再按主语言匹配（`ja-JP` → `ja`）；都不中用 zh-CN。

注意 `editor.phrases` 的**键是 CodeMirror 的英文原文**，不能翻译键，只翻译值；
`latex.commands` / `latex.envs` 的键是 LaTeX 命令名，只给常用的写说明，没写的不显示说明。

## 7. 宏包说明

设置页「已装宏包」里每个宏包的一句话说明，原文是 TeX Live 数据库里的英文（服务端
`case::installed_packages` 返回的 `desc`）。译文不进 `messages`：键是宏包名，数量随 TeX Live 变，
放进去会让每种语言都背上几百个必填键。

```
app/src/i18n/packages/
├── zh-CN.json       # 宏包名 → 说明，收录随应用内置的那些宏包
└── zh-TW.json       # 与 zh-CN 收录同一批宏包
```

- 界面里用 `packageDesc(name, desc)`：当前语言有译文用译文，没有就用英文原文。英文不需要文件。
- 内置语言之间收录的宏包必须一致，`check:i18n` 会核对（以 zh-CN 为准）。内置 TeX Live 的
  宏包清单（`scripts/texlive-packages.txt`）有增减时，两份一起补。补装进用户层的冷门宏包不收，显示英文。
- 新增内置语言时，宏包说明可以不做：不放 `packages/<代码>.json` 就全部显示英文；放了就要收齐同一批。
- **用户语言包**（`.subo-locale.json`）可带可选的 `packages` 字段，格式同上。没写的宏包显示英文，
  不走包的 `fallback`；与内置语言同代码的包，没写的沿用内置译文。不计入翻译覆盖率。

## 8. 守门：`npm run check:i18n`

`npm run build` 依次跑 `tsc`、`check:i18n`、`vite build`，任何一步失败都不出包。
`check:i18n`（`app/scripts/check-i18n.mjs`）用 TypeScript 语法树扫 `app/src/`（不含 `i18n/`），拦：

| 拦什么 | 例子 |
|---|---|
| 含中日韩文字的字符串、模板字符串、JSX 文本 | `toast("已保存")`、`<b>项目</b>` |
| JSX 里写死的字母文字 | `<button>Open</button>` |
| `title` / `placeholder` / `aria-label` / `alt` / `label` 写死字符串 | `title="Zoom in"` |

注释不算；`<Kbd>`、`<code>`、`<pre>` 里的内容不算（按键名、代码）。

确实不是界面文案的（装饰符号、匹配服务端日志的正则、字体试排样张、宏包名），在同一行或
所在语句前的注释里写 `i18n-ignore` 并**写明原因**：

```ts
// i18n-ignore：字盘里的装饰符号，不是界面文案，不随语言变
const GLYPHS = ["§", "永", ...];
```

`i18n-ignore` 是例外不是出口：评审时每一处都要问「这真的不该翻译吗」。

## 9. 范围与已知缺口

- **已覆盖**：前端全部界面（项目列表、工作区、文件树、预览、附件、快速打开、改名、提示、
  CodeMirror 搜索面板、LaTeX 补全说明）、窗口标题、`<html lang>`。
- **服务端错误**：`subo-server` 通过 HTTP 返回的错误统一是
  `{ code, params, message }`（`server/src/fail.rs`）。`code` 是稳定的错误码，前端
  `api.ts` 把它映射成 `t("server.<code>", params)`；语言文件里认不出的码退回 `message`
  （中文兜底），不是这个形状的响应原样显示正文。新增服务端错误时：
  1. 服务端用 `Fail::new("分组.键", "中文兜底").with("参数", 值)`，HTTP 状态码照旧；
  2. 在 `locales/zh-CN.ts` 的 `server` 分组加同名键，再补其他语言；占位符与 `with` 的参数名一致；
  3. 系统给的错误原文（`io::Error` 等）放 `{detail}`，不翻译；
  4. 错误码一旦发布不要改名，前端的旧键会失效。
- **仍未覆盖**：
  - 编译事件 `job.failed` 里的 `error`（「编译超时，已终止」等）、`engine.rs` 写进编译日志的
    提示：前端目前不显示 `error`，日志按原文展示。
  - 缺字安装 `case::install` 的失败原因（如「宏包名不合法」）仍是中文，整段放在
    `server.case.installFailed` 的 `{detail}` 里。
  - 终端里的启动信息（`println!`）只给开发者看，不翻译。
- 新建项目的模板（`library.rs` 里的 `main.tex`）是中文模板，属于内容，不随界面语言变。
- 语言偏好只存在本机 `localStorage`（`subo.locale`），和主题一样。
